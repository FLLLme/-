## 一个迟到的决定

我在三个不同的博客平台上写过东西。它们都很好用：注册即写，自带 CDN，评论、统计、SEO 一应俱全。但过去五年里，我经历了两次平台关停、一次域名被重定向到广告页。

> 数据放在别人的硬盘上，你拥有的只是**访问权**，不是**所有权**。

这不是平台的道德问题，而是商业模式的必然结果。免费托管的内容总有一天要为自己的服务器账单找到一个说法。

## 我真正想要的东西

梳理下来，需求其实非常朴素：

1. **文章是纯文本。** 最好是 Markdown，能用 Git 管理，能在任意编辑器里打开。
2. **站点是静态的。** 没有数据库、没有构建失败、没有依赖升级带来的连锁反应。
3. **评论可以换。** 评论系统是一个可插拔的外部依赖，不应该和内容耦合。
4. **AI 能被调用。** 读者读到不懂的地方时，应该能就地提问，而不是自己去别处复制粘贴。

第 4 点是这次重建最重要的增量。前三点是 2015 年的博客方案，第 4 点是 2026 年的。

## 技术选型

最终落地的方案刻意保持了简单：

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 内容 | Markdown 文件 + `manifest.json` | 零构建步骤，Git 友好 |
| 渲染 | 原生 DOM + 轻量 Markdown 解析 | 无框架，首屏无需等待 hydration |
| 样式 | 原生 CSS 自定义属性 | 主题切换只需改 20 个变量 |
| 评论 | Twikoo | 可自托管，数据在自己手里 |
| AI | DeepSeek API + 同源代理 | 兼顾流式体验与密钥安全 |

整个站点没有任何构建流程。改一篇文章就是改一个 `.md` 文件，刷新即可。

## 关于"不用框架"

这不是对框架的敌意。恰恰相反，如果这个站点有 200 个交互组件，我会毫不犹豫地上 React。

但对于一个博客，浏览器原生能力已经足够：

```js
// 列表渲染：模板字符串 + fragment
const frag = document.createDocumentFragment();
posts.forEach(p => frag.append(createCard(p)));
grid.replaceChildren(frag);
```

```css
/* 响应式网格：一行就够了 */
.post-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(320px, 1fr));
}
```

代价是大约 800 行 JavaScript，收益是一个 30KB 的站点和零维护成本。这笔账我认为是划算的。

## 一个细节：文章加载的两条路径

静态站点有个经典的矛盾：`fetch` 读本地 `.md` 文件在 `file://` 协议下会被浏览器的同源策略拦截。所以本站设计了双路径加载：

- **主路径**：通过 HTTP 服务访问时，直接 `fetch` 真实的 `.md` 文件。
- **兜底路径**：检测到 `file://` 协议时，改用随构建生成的 `posts/bundle.js`（由 `tools/bundle.py` 从同一批 `.md` 文件生成）。

这样双击 `index.html` 也能看到完整站点，同时保持 Markdown 文件是唯一事实来源。
